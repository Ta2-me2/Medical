# Medical — Архитектура

Персональный медицинский архив для macOS. Один пользователь, локальное хранение,
горизонт использования — десятилетия. Не EMR, не облако, не ИИ.

---

## 1. Главный принцип хранения

> Интерфейс — это только слой над структурированными данными, но никогда сами данные.

Отсюда следует главное архитектурное решение: **источник истины — папка на диске
(Library), а не база приложения.** Приложение можно удалить, переустановить,
переписать через 15 лет на другом фреймворке — архив останется читаемым.

```
~/Library/Application Support/Medical/
└── Medical Library/                ← перемещаемая папка, местоположение запоминается
├── Archive.json                    ← источник истины. Человекочитаемый, отформатированный.
├── Originals/
│   └── 2004/
│       └── 3f2a…d1-blood-test.pdf  ← оригинал, read-only, никогда не меняется
├── Snapshots/
│   ├── archive-2026-08-07-1943.json  ← версии на случай ошибки
│   └── archive-2026-07-31-1102.json
└── Library.json                    ← версия схемы, UUID архива, дата создания
```

**Почему Application Support, а не ~/Documents:**

Documents принадлежит человеку, а не программе. Папку, лежащую там, он вправе
переименовать, убрать в подпапку или перетащить на внешний диск — и каждое из
этих действий ломает приложение, которое держит её открытой. Application Support —
обратное обещание: это место, где программа хранит то, что ведёт от имени
владельца; оно переживает перетаскивание приложения в корзину. И главное: у
большинства включена синхронизация Desktop & Documents, то есть архив
медицинских записей молча уезжал в iCloud — при заявленном «local-first, без
облака». Application Support не синхронизируется.

Библиотеки, оставшиеся в `~/Documents`, переезжают один раз при запуске
(`ArchiveLocation.adoptLegacyLibraryIfNeeded`): папка перемещается целиком,
ничего не копируется вручную и ничего не перезаписывается. Если файлы ещё не
выкачаны из iCloud, переезд откладывается до следующего запуска — переносить
placeholder'ы значит перенести заглушки и потерять содержимое.

**Почему JSON, а не база данных:**

За всю жизнь у человека набирается порядка 1–3 тысяч медицинских событий.
Это файл на несколько мегабайт. SQLite здесь не даёт ничего, кроме зависимости
от формата и слоя миграций, — а стоит читаемости.

- `Archive.json` открывается любым текстовым редактором через 30 лет, без
  приложения, без библиотек, без документации формата. Ключи — человеческие слова.
- Запись атомарная: временный файл → `rename`. Прерывание питания не рвёт архив.
- Перед каждой записью прошлая версия уходит в `Snapshots/`.
- `Originals/` разложены по годам с человекочитаемым суффиксом в имени.
  Найти анализ 2011 года можно просто через Finder.

Если архив когда-нибудь вырастет до масштаба, где линейный поиск станет заметен,
за протоколом `ArchiveStore` появится второй бэкенд с индексом. Ни один экран
об этом не узнает.

Целостность: у каждого документа хранится SHA-256. Команда `Verify Archive Integrity`
проверяет, что ни один оригинал не подменён и не потерян.

## 2. Слои

```
Views (SwiftUI)      → только отображение, ничего не знают о хранилище
   ↓ @Observable
ViewModels           → состояние экрана, фильтры, сортировки, действия
   ↓ protocol
ArchiveStore         ← протокол. Views/VM ничего не знают о способе хранения
   ↓
FileArchiveStore + FileVault + ArchiveWriter (actor)
   ↓
Archive.json / Originals/ / Snapshots/
```

`ArchiveStore` как протокол — это и есть «support future database expansion».
Заменить хранилище через 10 лет = написать одну новую реализацию протокола,
не трогая ни один экран.

Доменные модели (`MedicalEvent`, `Patient`, …) — чистые Swift-структуры, `Codable`,
без зависимости от фреймворков. Они же — формат файла на диске. Одна модель,
никакого маппинга между «моделью для UI» и «моделью для базы», нечему разъезжаться.

## 3. Модель данных

Всё вращается вокруг **Medical Event**. Дублирования данных нет: прививка,
заметка, диагноз — всегда принадлежат событию.

Исключение — **документы**. И оно принципиальное:

> Документ — это оригинал. Medical Record — оболочка вокруг него, а не наоборот.

Документы лежат отдельной коллекцией верхнего уровня. Запись не владеет файлом —
она его **цитирует**: id документа плюс диапазон страниц.

```swift
struct DocumentReference {
    var documentID: UUID
    var pages: PageSelection    // пусто = весь документ
}
```

Это решает случай, ради которого всё и затевалось: детская карта на 90 страниц
приходит одним сканом. Резать её нельзя — оригинал есть доказательство. Поэтому
три разные записи ссылаются на страницы 15–17, 42–43 и 58 одного и того же файла,
и файл остаётся целым.

`PageSelection` хранится строкой — `"15-17, 42-43, 58"` — потому что именно так
человек надписывает папку, и через тридцать лет это будет так же понятно.
Диапазоны нормализуются при разборе: `3, 1-2, 2` превращается в `1-3`, одна и та
же страница не записывается дважды.

```swift
struct MedicalEvent {
    let id: UUID
    var date: DateValue          // ← см. ниже
    var endDate: DateValue?      // госпитализация, курс лечения
    var category: EventCategory
    var specialty: Specialty?
    var status: EventStatus      // normal | followUp | significant
    var isPinned: Bool           // держать на виду в Dashboard
    var title: String
    var summary: String
    var translations: [LanguageCode: TranslatedText]  // ручной перевод, без ИИ
    var doctor: Doctor?
    var facility: Facility?
    var diagnoses: [Diagnosis]      // текст + опциональный код МКБ-10
    var medications: [Medication]
    var vaccinations: [Vaccination]
    var documentIDs: [UUID]         // ссылки в библиотеку документов
    var notes: [Note]
    var tags: [Tag]
    var createdAt, updatedAt: Date
}
```

### DateValue — неочевидная, но критичная деталь

В архиве за 20 лет часть бумажных документов датирована неточно: «март 2007» или
просто «2004». Обычный `Date` заставит выдумывать день — и архив начнёт врать.

```swift
struct DateValue {          // дата + её точность
    var date: Date
    var precision: Precision   // .day | .month | .year
}
```

Timeline и экспорт отображают ровно ту точность, которая известна: `2004`,
`Март 2007`, `14 марта 2007`.

### EventStatus — единственный цвет в интерфейсе

`normal` · `followUp` · `significant`. Ставится только вручную: приложение не
имеет мнения о том, хорошая новость в документе или плохая, а догадка здесь
хуже отсутствия ответа.

Цвет один и тот же везде, где событие показывается — точка на линии времени,
чип в карточке, точка в результатах поиска. Подпись при этом рисуется только у
`followUp` и `significant`: `normal` — состояние покоя почти каждого события в
двадцатилетнем архиве, и подписывать их все значит похоронить те два статуса,
которые что-то значат.

### ResultTable — то, что читает врач

Скан русского бланка — доказательство, но не то, чем может пользоваться врач в
другой стране. Рядом с ним живёт таблица, набранная владельцем по-английски:

```swift
struct ResultTable {
    var title: String
    var columns: [String]       // "Test" / "Result" / "Reference" — или любые
    var rows: [ResultRow]       // + пометка «вне нормы», вручную
}
```

Схемы нет намеренно: ни одна не переживёт двадцати лет бумаг из нескольких стран.
Столбцы задаёт владелец, пресеты — только заготовки.

Отметка «вне нормы» ставится руками. Референсные интервалы отличаются по
лаборатории, возрасту и методу; догадка, напечатанная рядом с результатом крови,
хуже отсутствия отметки.

Таблицы попадают в Doctor Report как настоящие таблицы PDF — с повторением
шапки при переносе на следующую страницу.

### Inbox и DocumentStatus

Импорт заканчивается на пороге: файлы попадают в библиотеку и в Inbox, но не
становятся медицинскими записями. Это единственный способ разобрать пачку из
полутора сотен сканов — импортировать всё сразу, а разбирать неделями.

```
Import  →  Inbox  →  Medical Record
```

Импорт живёт **внутри** Inbox, а не отдельным разделом: положить файл в инбокс и
смотреть в инбокс — одна и та же задача, и отдельный пункт меню для неё был
лишним шагом навигации.

`DocumentStatus` — `notProcessed` · `used` · `archived`. На диске хранится
только `isArchived`; «использован» вычисляется из того, ссылается ли на документ
хоть одна запись. Хранимый флаг рано или поздно начал бы утверждать «used» про
документ, на который уже никто не смотрит.

Удаление записи не трогает её документы: они остаются в библиотеке и
возвращаются в Inbox, если на них не ссылается никто другой. Байты — единственное
в этом архиве, что нельзя восстановить.

`archived` — отдельный раздел, а не корзина: детские патронажи, страховки, старые
выписки. Они ищутся наравне со всем остальным, но в Timeline не попадают, потому
что событиями жизни не являются. Любой из них можно вернуть в Inbox и сделать
полноценной записью.

### Удаление

Единственная операция в приложении, способная что-то потерять, поэтому она
никогда не в один клик. Диалог говорит, сколько файлов, предупреждает, если на
документ ещё ссылается запись, и заставляет выбрать судьбу байтов:

- **Move Files to Trash** — в системную Корзину, откуда Finder их вернёт.
- **Keep Files, Remove from Archive** — в папку `Removed/` внутри библиотеки.

Приложение не умеет удалять оригинал безвозвратно ни при каком выборе. Порядок
операций тоже важен: сначала файл, потом запись о нём, — чтобы неудачное
перемещение оставило архив ссылающимся на существующий файл, а не наоборот.

`Start a New Library` — чистый лист: рядом создаётся пустая библиотека,
приложение переключается на неё, прежняя остаётся на диске нетронутой.

### Справочники

`Doctor`, `Facility` (клиника/больница), `Tag` — отдельные сущности с
переиспользованием: врач заводится один раз и связывается с любым числом событий.
Поиск «все визиты к Иванову» становится тривиальным.

### StoredDocument

```swift
struct StoredDocument {
    let id: UUID
    let originalFilename: String   // как файл назывался при импорте
    let relativePath: String       // Originals/2011/…
    let contentHash: String        // SHA-256
    let byteSize: Int
    let kind: DocumentKind         // pdf | image | scan
    let pageCount: Int?
    let importedAt: Date
    var eventID: UUID?
}
```

Оригинал read-only. Приложение не умеет его редактировать — только читать,
показывать превью и копировать при экспорте.

### Повторные прививки

У прививки может быть расписание повтора: интервал (`afterMonths`) или конкретная
дата от клиники. Ставится вручную — расписания отличаются по стране, препарату и
истории человека, и выдуманное приложением было бы хуже пустого поля.

Ключевое правило: **отсчёт идёт от реально сделанной прививки, а не от плана**.
Вторая доза полностью заменяет расписание первой, независимо от того, сделана она
раньше срока или позже. Поэтому на каждую вакцину всегда ровно один ответ — тот,
что следует из последней дозы. Вакцины сопоставляются по имени без учёта регистра.

На Dashboard попадают только просроченные и то, что наступает в ближайшие 12
месяцев, максимум три строки: напоминание за четыре года — не напоминание, а
Dashboard, превратившийся в календарь прививок, перестаёт быть рабочим экраном.

### Doctor Report и резервная копия

Из архива выходят две вещи, и это не варианты одного и того же.

**Doctor Report** — для человека: история, цифры на языке, который он читает, и
ровно те страницы, на которые ссылаются записи. Отдавать девяностостраничную
карту, когда важны три страницы, — не добросовестность, а способ похоронить
ответ. Оригинал при этом не меняется: страницы копируются в новый PDF.

**Export Library** — для машины: вся папка байт в байт, обычным zip через
системный `ditto`. Восстановление — это распаковка, а не импорт, и оно никогда не
пишет поверх существующей библиотеки: копия раскладывается рядом, приложение
переключается на неё.

### Категории

Consultation · Laboratory · Diagnostics · Imaging · Surgery · Hospitalization ·
Vaccination · Dental · Vision · Prescription · Emergency · Screening ·
Certificate · Other

## 4. Экраны

| Раздел | SF Symbol | Ключевое решение |
|---|---|---|
| Dashboard | `house` | Рабочий экран, не табло. Закреплённое, последние события, последние документы (с отметкой, разложены ли), последние заметки. Никакой статистики: число документов ни на что не влияет. |
| Timeline | `calendar` | Одна непрерывная вертикальная линия: годы и события — узлы на одной нити, линия между ними не рвётся. Рельс лет слева; скролл подсвечивает год, клик по году — плавный скролл. |
| Inbox | `tray` | Очередь разбора и точка входа для импорта. Название, размер, число страниц, дата импорта, статус. Множественный выбор и удаление. Счётчик в сайдбаре — не статистика, а долг. |
| Documents | `text.document` | Библиотека, а не список файлов: формат, число страниц, дата, «Used in N medical records». Открытие — Quick Look слева, метаданные справа. |
| Vaccinations | `syringe` | Что предстоит — сверху, затем вертикальный таймлайн доз с рельсом и точками. |
| First Aid Kit | `cross.case` | Чего не хватает — сверху, затем сроки годности, затем полки: плитки со стикерами, сгруппированные по назначению. Инвентарь, а не история. |
| Notes | `text.page` | Плоский список, поиск, фильтр, каждая ведёт к своему событию. |
| Export | `square.and.arrow.up` | Одна кнопка **Doctor Report**: отчёт, английские таблицы, процитированные страницы оригиналов — одним архивом. Отдельно — резервная копия библиотеки и восстановление. |
| Patient | аватар | Карточка-паспорт. Medical Alerts красной секцией сверху, если есть. |

Навигация: `NavigationSplitView` (sidebar + detail), внутри detail — `NavigationStack`
со своим путём на раздел, чтобы возврат работал предсказуемо.

## 5. Визуальный язык

Единая design-система в `DesignSystem/`, никаких «магических чисел» по экранам.

- **Цвет.** Оттенки серого. `accentColor` — только выделение. `.red` — критические
  предупреждения (аллергии, alerts), `.orange` — предупреждения, `.green` —
  завершённый статус. Больше ничего.
- **Категории событий** не раскрашиваются. Отличаются символом и подписью —
  иначе таймлайн превратится в светофор. Цветом владеет только `EventStatus`,
  и потому цвет в этом приложении всегда значит одно и то же.
- **Типографика.** Только системные стили (`.largeTitle` … `.caption`), SF Pro.
- **Материалы.** Никаких градиентов и теней. Разделители — hairline.
- **Скругления.** 10–12 pt для карточек, `.rect(cornerRadius:style: .continuous)`.
- **Пустые состояния.** `ContentUnavailableView` везде — это часть дизайна,
  а не заглушка. Архив в начале пуст, и эти экраны пользователь увидит первыми.

## 6. Структура кода

```
Medical/
├── App/              MedicalApp, AppSettings, Commands (меню)
├── Model/            Чистый домен. Zero imports кроме Foundation.
├── Persistence/      ArchiveStore (protocol), SwiftDataArchiveStore,
│                     Schema/V1, FileVault, SnapshotWriter, LibraryLocator
├── DesignSystem/     Spacing, Typography, Palette, Components/
├── Features/         Dashboard/ Timeline/ Documents/ Import/ Vaccinations/
│                     FirstAidKit/ Notes/ Export/ Patient/ EventDetail/ Search/
│                     — каждая: View + ViewModel
├── Services/         ImportService, ExportService, SearchIndex,
│                     ThumbnailService, IntegrityChecker
└── Resources/        Assets.xcassets, локализации
```

Каждая фича изолирована и зависит только от `Model` + `ArchiveStore` + `DesignSystem`.
Фичи не знают друг о друге — переход между ними идёт через роутер в `App/`.

## 7. Что сознательно не делается

- Нет облака, аккаунтов, синхронизации.
- Нет ИИ, автораспознавания, автозаполнения из документов.
- Нет редактирования оригиналов.
- Нет страницы настроек (по ТЗ). Расположение библиотеки и обслуживание архива —
  в меню приложения, там же, где это ожидаемо в macOS.
